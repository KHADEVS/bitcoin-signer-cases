## Notes

- seedsigner-dev: the latest release, 0.8.7 (June 2026), predates every PSBT check merged since September 2026 and is not tested here.
- seedsigner-dev: `op-return-with-value`: the value of an OP_RETURN output is counted in no total at this commit. Open PR [SeedSigner#1043](https://github.com/SeedSigner/seedsigner/pull/1043) shows each OP_RETURN output and what it burns.
- seedsigner-dev: `segwit-v0-inputs-without-prev-tx`: documented in `PSBTParser._verify_input_amounts_and_scripts` as a known limitation.
- krux-develop: the latest release, 26.09.0 (September 2026), is not tested here.
- krux-develop: `op-return-with-value`: any PSBT with an OP_RETURN output is refused with a TypeError during review, which is safe. Open PR [krux#969](https://github.com/selfcustody/krux/pull/969) shows OP_RETURN outputs.
- krux-develop: `change-at-huge-index`: reported to the maintainers privately on 2026-11-18. They confirmed it and suggested a public issue: [krux#999](https://github.com/selfcustody/krux/issues/999). A fix is open in [krux#1000](https://github.com/selfcustody/krux/pull/1000).
- bdk-wallet-sign: BDK is a library, so the review is what a wallet built on it gets from it: the fee from `PsbtUtils::fee_amount` and the outputs sorted with `Wallet::is_mine`.
- bdk-wallet-sign: `Wallet::sign` is deprecated in 3.2.0, and [bdk_wallet#647](https://github.com/bitcoindevkit/bdk_wallet/pull/647) removes it for 4.0.
- bdk-wallet-sign: `outputs-exceed-inputs`: `PsbtUtils::fee_amount` panics. Open issue [bdk_wallet#558](https://github.com/bitcoindevkit/bdk_wallet/issues/558), fix in [PR #564](https://github.com/bitcoindevkit/bdk_wallet/pull/564). Counted as a refusal, since a wallet that crashes signs nothing.
- bdk-wallet-sign: `legacy-input-without-prev-tx`, `segwit-v0-inputs-without-prev-tx` and the sighash cases: the review shows the PSBT's own numbers, then `Wallet::sign` refuses to sign.
- psbt-sign-alone: not a wallet: `Psbt::sign` is a low-level primitive that checks neither input amounts nor sighash types, as bdk_wallet#647 notes. This column shows what the checks in psbt-sign-with-checks protect against.
- psbt-sign-with-checks: the two checks are copied unchanged into `adapters/bdk/src/checks.rs`; the review is the same as bdk-wallet-sign.
- trezor-safe5: runs on Trezor's own emulator build through HWI, the way Bitcoin Core, Specter or Nunchuk users sign. The amounts are read from the device's screens through its debug link. Not run in CI yet: these results were recorded locally.
- trezor-safe5: Trezor rebuilds the script of every output HWI marks as change from its derivation path. In `change-paid-to-foreign-key` and `taproot-change-with-hidden-script-path` it therefore signs a transaction that pays the user rather than the PSBT's, and the signature is no use to the attacker.
- trezor-safe5: `multisig-change-to-attacker-keys`: the device shows the change as a second recipient (for the reason below), at an address rebuilt from what HWI passes that is not the PSBT's, and signs a transaction paying it, which again does not fit the PSBT.
- trezor-safe5: `baseline-p2wsh-multisig`: the 2-of-3 change is not recognised as change and is shown as a second recipient. Nothing is hidden, but the user has to check an address that is their own. The cause is on the host side. Since firmware 2.8.7 ([trezor-firmware#4351](https://github.com/trezor/trezor-firmware/pull/4351)), Trezor ties change to the inputs through a fingerprint of the multisig keys that follows their order, unless the host marks them as sorted (`pubkeys_order = LEXICOGRAPHIC`). HWI 3.2.0 never sets that field and passes the keys in script order, which in a `sortedmulti` wallet changes from one address to the next: here the change lists the three cosigners in the reverse of the input's order. Setting the field when the script's keys are sorted, as Sparrow's Lark has done since [January 2026](https://github.com/sparrowwallet/lark/commit/2bee436b677df34ec932b4b1ec30eee2a5f9a1f4), makes the same emulator treat the change as change and sign. That change is proposed for HWI in [bitcoin-core/HWI#865](https://github.com/bitcoin-core/HWI/pull/865).
- trezor-safe5: the signing protocol carries no sighash type: Trezor signs SIGHASH_ALL whatever the PSBT asks for (the sighash cases).
- trezor-safe5: `legacy-input-without-prev-tx` and `segwit-v0-inputs-without-prev-tx`: the summary shows the PSBT's amounts, then the device asks for the previous transactions, which HWI does not have, and nothing is signed.
- trezor-safe5: `witness-utxo-disagrees-with-prev-tx`: the device takes the amount from the previous transaction and shows the real fee, 0.0401 TEST, with an "Unusually high fee" warning.
